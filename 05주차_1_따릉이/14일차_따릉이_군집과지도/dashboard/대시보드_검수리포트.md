## 2. 계산 검증

### 2-1. 표준화 (StandardScaler와 동일)

브라우저에서 계산한 값 (모집단 표준편차, ddof=0):

| 변수 | 평균 | 표준편차 |
| --- | ---: | ---: |
| 일평균이용건수 | 37.9846 | 34.3072 |
| 출근시간비중 | 0.1773 | 0.0799 |
| 퇴근시간비중 | 0.2897 | 0.0765 |
| 주말비중 | 0.2469 | 0.0629 |
| 거치대당일평균이용건수 | 3.3418 | 2.8797 |

Python `StandardScaler().fit(df[V])` 의 `mean_` / `scale_` 와 소수 네 자리까지
일치한다.

### 2-2. ★ 가중치가 제곱으로 반영되지 않는지

가장 중요한 항목이다. `w = [40,15,15,15,15]` 를 넣고 첫 대여소의 실제 KMeans
입력 좌표를 꺼내, 두 후보식과 각각 비교했다.

| 비교 대상 | 최대 절대차 | 판정 |
| --- | ---: | --- |
| `z × √w` (의도한 식) | **0.00e+00** | 일치 |
| `z × w` (흔한 실수) | 6.29e-01 | 불일치 |

즉 실제로 `표준화값 × √(정규화 가중치)` 가 들어간다. 가중치 정규화 합계도
`1.0`(오차 < 1e-12)로 확인했다.

### 2-3. 정규화 — 합계가 100%가 아닌 입력

각 10%(합계 50%)를 넣고 재계산했을 때 각 20%(합계 100%) 결과와
**군집 변경 대여소 0곳 · 군집 크기 동일**이었다. 비율만 같으면 같은 결과가 나온다.

### 2-4. 재현성

같은 가중치(각 20%)로 연속 두 번 재계산해 2,782개 라벨이 전부 동일했고,
최초 로드 시 결과와도 동일했다. `Math.random`을 쓰지 않고 고정 시드 LCG를 쓴다.

### 2-5. scikit-learn과 같은 해에 도달하는지

기본 가중치 결과의 inertia를 표준화 공간으로 환산해 비교했다.

| 계산 주체 | inertia | 군집 크기(정렬) |
| --- | ---: | --- |
| 브라우저 (고정 시드 5회) | **7086.3344** | 355 / 422 / 888 / 1,117 |
| sklearn `n_init=20` | 7086.3414 | 356 / 422 / 886 / 1,118 |
| sklearn `n_init=50` | 7086.3358 | 355 / 422 / 886 / 1,119 |
| sklearn `n_init=200` | 7086.3305 | 355 / 422 / 887 / 1,118 |

**같은 해다.** 이 데이터의 최적해는 매우 평평해서 sklearn 자체도 `n_init`에
따라 경계 대여소 1~2곳이 오간다. 브라우저 결과는 sklearn `n_init=200` 과
inertia 차이가 0.004 수준이다.

> **발표자료와의 1~3곳 차이:** 발표자료
> (`발표자료/10_국내데이터분석실전_13~16일차/`)는 sklearn `n_init=20` 결과라
> 356 / 422 / 1,118 / 886 으로 적혀 있고, 이 화면은 355 / 422 / 1,117 / 888 이다.
> 오류가 아니라 두 중심에서 거의 같은 거리에 있는 경계 대여소가 갈리는 것이다.
> 수업에서 숫자가 1곳 다르면 이 사실을 그대로 설명하면 된다 — "군집 경계에 있는
> 대여소는 어느 쪽으로도 갈 수 있다"는 것이 오히려 유용한 관찰이다.

## 3. 가중치를 바꿨을 때 (군집 변경 대여소 수 > 0)

| 가중치 (일평균/출근/퇴근/주말/거치대당) | 변경 대여소 | 군집 크기 | 번호 매칭 |
| --- | ---: | --- | --- |
| 20 / 20 / 20 / 20 / 20 (기본) | 0곳 | 355 / 422 / 1,117 / 888 | — |
| 5 / **80** / 5 / 5 / 5 | **2,057곳** (73.9%) | 715 / 1,009 / 762 / 296 | 2→3→0→1 |
| **80** / 5 / 5 / 5 / 5 | **1,713곳** (61.6%) | 333 / 58 / 885 / 1,506 | 3→1→0→2 |
| 10 / 10 / 10 / 10 / 10 (합계 50%) | 0곳 | 355 / 422 / 1,117 / 888 | — |

출근 가중치 80%일 때 군집 2·3이 모두 "출근 집중형 후보"로 나온다(출근 23.3% ·
32.6%). 번호는 최소거리 매칭으로 이어졌지만 내용은 달라진 것으로,
README 7절에 한계로 적어둔 상황이 실제로 나타난 예다. 수업에서 이 화면을
띄워놓고 "번호가 이어졌는데 성격이 같다고 볼 수 있나"를 물으면 좋다.

이용건수 가중치 80%일 때 군집 1이 58곳으로 줄어든다. 발표자료 05장
(표준화 없이 k=4)에서 나온 58곳과 같은 숫자다 — 가중치를 한 변수로 몰면
표준화를 안 한 상태에 가까워진다는 것을 화면에서 확인할 수 있다.

| 3 | 태블릿(1024px)에서 지도가 왼쪽 패널과 나란히 놓여 먼저 좁아짐 | 지도를 1행 전폭으로, 가중치·요약을 2행 2열로 재배치 |
| 4 | Playwright에서 `map.invalidateSize()` 반환값 직렬화 실패 | 평가식 끝에 `return null` 추가 |
| 5 | 스크린샷이 직전 검사 때문에 특정 대여소로 확대된 상태로 찍힘 | 촬영 전 서울 전체 뷰·패널 스크롤 초기화 |

## 9. 이 화면으로 말할 수 없는 것

README 9절과 같다. 화면 왼쪽 아래 "화면을 읽을 때 지켜야 하는 것" 상자에
네 문장이 항상 떠 있다.

- 군집은 운영 유형을 탐색하기 위한 그룹이며 우수·열등 순위가 아니다.
- 가중치는 어떤 변수를 군집 간 거리에서 더 중요하게 볼지 정한다.
- 지도만으로 업무지구·주거지·관광지 또는 실제 품절 원인을 단정할 수 없다.
- 현재 데이터에는 실시간 재고·대여 실패·반납 실패가 없다.
